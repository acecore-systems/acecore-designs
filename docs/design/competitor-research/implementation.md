# 競合調査を踏まえたサイト改善

確認日: 2026-10-18（JST）。基点: `ff2c807`。対象: Acecore Designs。

## 改善の狙い

制作名称が分かる人は従来の料金一覧へ、まだ名称が分からない人は用途別入口へ進める。相談前に制作工程と確認項目を把握でき、各サービスの選択をAcecore法人窓口へ引き継げる構成にする。

## 実画面から採用した考え方

| 公式ページ                                                     | 実見した構成                                                         | 採用する点                               | 適用しない点                                           |
| -------------------------------------------------------------- | -------------------------------------------------------------------- | ---------------------------------------- | ------------------------------------------------------ |
| [410STUDIO / 3D制作](https://www.410studio.co.jp/services/3d)  | サービス別ナビ、用途、対応内容、工程、相談前情報、FAQ                | 用途から探す入口、工程と相談前情報の分離 | 同社の対応形式、納期、実績を自社の事実にしない         |
| [GIKUTAS](https://gikutas.jp/)                                 | 作品を大きく見せるヒーロー、問い合わせと工程への入口、制作体制の説明 | 料金を見る入口と相談する入口を併設       | クリエイター人数、顧客数、品質保証表現、作品画像の流用 |
| [VOICE MART / 宅録](https://www.voice-mart.jp/home-recording/) | 用途を説明する導入、料金・依頼手順・FAQへの導線、条件を添えた実績値  | 相談前の確認事項と条件の可視化           | 同社の納期、所属人数、録音体制、使用条件の自社への転用 |

上記はBrowser/IABで実画面とDOMを確認。競合の成約率やサイト改善効果は測定していない。構成の採用理由はUX上の判断であり、売上改善の実証ではない。

## 実装

- ヒーロー: 既存見出し・説明を保ち、3分野へのリンクと相談CTAを追加。
- 用途別入口: キャラクター、商品・情報、立体・動きの3入口に13サービスを割り当てる。表示名は各言語のカタログから参照し、別の制作カタログを作らない。
- 料金一覧: 既存のカード、税込開始価格、説明、個別問い合わせURLを保持。用途別リンクで移動したカードを枠線で強調。
- 工程: 既存の工程説明を4段階で読みやすく提示。
- 相談前情報: 用途、制作範囲、納期、形式・環境、資料、利用条件・修正を列挙。確約条件や新しい必須入力を設定するものではない。
- FAQ: 価格・工程・制作担当・研修への質問。回答は既存のカタログ本文を参照。
- 末尾: 法人相談CTA、Hattの公開作品、Schoolsを役割別に案内。
- 追加のUI文言は日本語と8翻訳へ反映。価格・契約条件を翻訳UIへ重複して保持しない。

## 維持する契約

`src/content/catalog` の全ファイルに実質変更なし。13サービスのID・名称・説明・価格、9言語、`catalog.json` の `schemaVersion: 1` / `sourceUrl` / `locales` を保持。問い合わせのlocale、`category=service&service=acecore-design&offering=<id>#contact-form` を保持。CMS・決済・認証は追加していない。

## デザイン仕様と画像の扱い

`concepts/top.png`、`concepts/catalog.png`、`concepts/guidance.png` は内部レビュー用の生成UI案。実績や制作物としてサイトに掲載しない。実装には既存のブランドSVGを使う。

採用する仕様は紺 `#00022b`、青 `#063d91`、白、淡青 `#eef6ff`、既存の角丸カード、罫線によるグループ分け、広い余白、文字主体のサービス索引。新しい制作画像は使わない。

画像生成で補われた文案・ナビは採用しない。既存カタログとブランドを優先するため、以下を意図的な差分とする。

| 比較点            | 実装上の判断                                                                                  |
| ----------------- | --------------------------------------------------------------------------------------------- |
| ロゴ・ヘッダー    | 既存ロゴと9言語メニューを保持。画像案の仮ロゴや存在しないニュース・実績ページへのナビは不採用 |
| ヒーロー本文      | 正本の見出し・説明と一致。日本語は読点後の改行のみ追加。装飾の英語ラベルを削除                |
| 用途別サービス名  | 画像案の略称ではなく正本の正式名称を使用                                                      |
| カタログ          | 既存の本文・価格・3列カードを保持。画像案の追加の価格注記帯や推測された下段本文は不採用       |
| 工程とFAQ         | 既存の左揃え見出しと本文を残す。FAQは既存本文で回答できる4問に限定                            |
| 相談前のアイコン  | 架空の保証に見せず、小さなチェックとして提示                                                  |
| 制作担当・Schools | 正本の説明を省略しないため、相談帯の下に独立して配置                                          |

画像案と実装を `view_image` で比較し、文案・構造・書体階層・配色・カード/罫線・矢印・余白・モバイル表示を確認する。生成画像とのピクセル単位の一致やユーザーによるデザイン承認を主張するものではない。

## 検証

- `npm run format:check`
- `npm run validate:content`: 21テスト。用途別の全13IDの到達可能性と追加UIの9言語構造も確認。
- `npm run build`: 全18ページ、13価格×9言語、公開JSON、問い合わせURL、内部リンク・アセット、canonical/hreflang/OG、sitemap、404を検証。
- `git diff --check`
- Browser/IAB: desktop 1036×720、mobile 390×720を撮影。1440×1100でもDOMの幅を確認したが、当環境の大きなスクリーンショットには繰り返し描画が生じたため、同寸の視覚比較は未完了。保存画像は重複描画がない1036×720/390×720。
- 全9言語の390px幅で横方向のoverflowなし、サービスカード13、用途別入口13、FAQ4を確認。
- モバイルメニューの開閉・項目選択後の閉鎖、用途リンクから該当カードへの移動と強調、FAQの開閉を確認。
- 言語メニューからロシア語→日本語へ遷移。法人問い合わせページでAcecore Designsが選択され、件名へキャラクターデザインが引き継がれることを確認。
- 問い合わせ送信、メール送信、実注文は行っていない。

Windowsの`core.autocrlf=true`により、基点の未変更ファイルでPrettierの改行警告が発生。`.gitattributes`でテキストをLFに固定し、正本の内容を変更せず検証が再現できるようにした。

## 事業判断・素材の準備が必要な次段階

1. 許諾と担当範囲を確認したHattの代表作を選定し、用途・制作範囲の説明とともに掲載する。現在の外部作品リンクだけでは、サイト内で品質を判断しにくい。
2. 音声サンプル、3Dの回転表示、制作前後の比較を、本人の実作品と掲載許可に基づいて用意する。
3. 標準納期、修正回数、納品形式、利用条件、追加費用の扱いを実務と照合して決める。競合条件をそのまま自社の約束にしない。
4. サービスごとの独立ページは、公開できる素材・具体的な依頼例・固有FAQがそろったものから追加する。現行カードを複製しただけの薄いページを量産しない。

## 公開と後処理

merge・本番公開は本タスクに含まない。Draft PRでレビューする。GitHub連携Pagesのpreview/CIは別途その実状態を記録する。本番のGit Provider・domain active・production deployをローカル検証の成功から推定しない。

作業終了時に今回の調査・ローカル検証・一時Chatのタブを閉じ、ローカル検証サーバーを停止する。作業ブランチはDraft PRのため保持し、無関係な既存タブ・ブランチは触らない。
